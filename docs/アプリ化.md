# アプリ化(Android / iOS)と画面の崩れのテスト

大学ノートは、ブラウザ版(PWA)と同じ画面のファイルを [Capacitor](https://capacitorjs.com/) でアプリに包んでいる。
画面のコードは1つだけで、ブラウザ版・Android 版・iOS 版のどれにも同じものが入る。

```
index.html・style.css・js/・vendor/・icons/
   │  npm run build:web(www/ にコピーするだけ。変換はしない)
   ▼
www/ ──┬─ GitHub Pages(ブラウザ版)
       ├─ npx cap sync android → android/(Android Studio のプロジェクト)
       └─ npx cap sync ios     → ios/(Xcode のプロジェクト。Mac が要る)
```

## ブラウザ版とアプリ版の違い

違いは `js/native.js` に集めてある。ブラウザでは今までどおりに動く。

| | ブラウザ版 | アプリ版 |
|---|---|---|
| WebDAV 同期 | `fetch`(サーバー側で CORS の許可が要る) | OS の通信機能を直接使う。**CORS の設定は要らない** |
| 書き出し(PDF・同期ファイル) | ダウンロード | Android: 保存先を選ぶ画面(「ダウンロード」・Google ドライブなど)。iOS: 共有シート(「"ファイル"に保存」・AirDrop など) |
| オフライン起動 | サービスワーカーのキャッシュ | 中身がアプリに入っている(サービスワーカーは使わない) |
| Android の「戻る」 | — | メニュー → ダイアログ → 重ねて出したページ一覧 → 投げ縄の選択 → ノートから本棚 → 検索 の順に閉じる。本棚ではアプリを裏に回す |
| 画面の端(切り欠き・ナビゲーションバー) | `env(safe-area-inset-*)` | Android は Capacitor が入れる `--safe-area-inset-*`、iOS は `env()` |

### WebDAV の通信

- **Android**: このアプリ専用のプラグイン `DavHttp`(`android/app/src/main/java/io/github/jagjagyt/daigakunote/DavHttpPlugin.java`)。
  OkHttp で送る。Capacitor 標準の CapacitorHttp は Java の HttpURLConnection を使うので、WebDAV に必要な
  `PROPFIND`・`MKCOL` を送れない(送ると例外になる)ため、自分で用意した。
- **iOS**: Capacitor 標準の CapacitorHttp(URLSession はどのメソッドでも送れる)。
- 時間切れは「何も届かない(送れない)時間が60秒」。ブラウザ版と同じ考え方。
- Android では、大きな PDF でもメモリが足りなくならないよう、本文は画面とアプリの中身のあいだで一度に渡さず、
  キャッシュのファイルを通す(送る本文は約 768KB ずつ書き足し、受け取った本文はファイルの URL で読む)。
  iOS はまだ一度に渡しているので、数十 MB の PDF で問題が出ないかは Mac で確かめる必要がある
- Android はリダイレクト(3xx)を追いかけない。OkHttp は 301・302 で PUT・MKCOL を GET に変えて追いかけるので、
  「送れたことになったのに届いていない」が起きるため。フォルダの URL は移動先の正しいものを入れる
- アプリ版がつながるのは **https:// のサーバーだけ**(Android・iOS とも、暗号化なしの通信は OS が止める)。
  http:// を入れると、そのことを知らせる
- `CapacitorHttp` の「fetch を全部すり替える」設定はオフにしている。すり替えると、PDF などのバイナリを
  文字として送ってしまい壊れるため(`capacitor.config.json` の `CapacitorHttp.enabled: false`)。

### データについて

ブラウザ版とアプリ版はデータの置き場所が別(同じ端末でも別のノート一覧になる)。
移すときはクラウド同期を使うか、「同期ファイルを書き出す / 取り込む」を使う。

ノートはアプリの中(WebView の IndexedDB)だけにある。**次のときは消える**ので、クラウド同期か書き出しで控えを持っておく:

- アプリをアンインストールしたとき、「設定 → アプリ → 大学ノート → ストレージ → データを削除」をしたとき
- iOS で端末の空き容量がとても少なくなったとき(OS が消すことがある)

ほかに気をつけること:

- Android の自動バックアップ・機種変更の引き継ぎには**入れていない**(`android:allowBackup="false"` と
  `res/xml/data_extraction_rules.xml`)。入れると、引き継いだ2台が同じ端末 ID になり、同期で線が消えるため。
  新しい端末へはクラウド同期で移す。同期のパスワードもこの端末の中だけに残る
- `capacitor.config.json` に `server.hostname`・`androidScheme`・`iosScheme` を書き足さない。
  画面の置き場所(オリジン)が変わると、それまでのノートが見えなくなる

## Android: Windows で動かして確かめる

### 準備(最初の1回)

1. [Android Studio](https://developer.android.com/studio) を入れる(Android の SDK・エミュレーターも一緒に入る)
2. Node.js 22 以上を入れる
3. このリポジトリを手元に置き、フォルダで `npm ci`

### エミュレーターで動かす

1. `npm run android`
   (画面のファイルを `www/` に集め → `android/` に入れ → Android Studio でプロジェクトを開く)
2. Android Studio の右上の「Device Manager」で仮想端末を作る。おすすめ:
   - タブレット: Pixel Tablet(Android 16 / API 36)… 大学ノートはタブレットが本番なので、こちらを主に見る
   - スマホ: Pixel 8(Android 16 / API 36)。画面の端(切り欠き・ナビゲーションバー)の確かめに
   - 古い端末の確かめ: Android 10(API 29)くらいを1つ。**Google Play 入りのシステムイメージ**を選び、Play ストアで「Android System WebView」を更新してから試す
     (アプリ版は Chrome 111 相当以上の WebView が要る。`color-mix()` などを使っているため。古い WebView では画面の端の扱いも違う)
3. 上の ▶(Run 'app')を押すと、エミュレーターが起動してアプリが入る
4. 画面を直したら、もう一度 `npm run cap:sync` → ▶

エミュレーターでのペン: マウスでのドラッグは「指」として届く。ペンで書くのを試すには、
メニュー(右上の …)の「指で書く」をオンにする。筆圧は実機でしか確かめられない。

WebDAV 同期をエミュレーターで試すとき、PC で動かしたテスト用サーバーは `http://10.0.2.2:<ポート>/` で見える。
ただし アプリ版は `http://`(暗号化なし)のサーバーにはつながらないので、試すには https のサーバー(InfiniCLOUD など)を使う。

### 実機(Android のスマホ・タブレット)で動かす

1. 端末の「設定 → デバイス情報 → ビルド番号」を7回押して開発者向けオプションを出し、「USB デバッグ」をオンにする
2. USB でつなぎ、Android Studio の端末の選択でその端末を選んで ▶

### Android Studio を入れずに試す

GitHub でプッシュするたびに、Actions の「確認」が APK を作る。
Actions の実行結果の下の「Artifacts」から `daigaku-note-debug-apk` をダウンロードし、
中の `app-debug.apk` を Android 端末に送って開くと入れられる(「提供元不明のアプリ」を許可する必要がある)。

- 署名の鍵(デバッグ用。`android/app/debug.keystore`)と版の番号(作った時刻から決める)を固定しているので、
  新しい APK は前の版の**上から入れ直せる**(ノートは残る)。Android Studio で入れた版とも同じ鍵
- 入れ直せないと言われても、**アンインストールはしない**(ノートが消える)。先に同期か書き出しをしてから
- デバッグ版なので、PC の Chrome の `chrome://inspect` から画面を調べられる。Capacitor のログは、同期のパスワードがログに残らないよう本番と同じく絞っている(`capacitor.config.json` の `loggingBehavior`)。人に配るのはリリース版で

### Google Play に出すとき(まだやっていないこと)

- 開発者登録(25ドル・1回だけ)
- 署名の鍵を作り、リリース版(`./gradlew bundleRelease` の .aab)を作る。鍵は絶対にリポジトリに入れない
- アプリの ID は `io.github.jagjagyt.daigakunote`(`capacitor.config.json`)。**ストアに出したあとは変えられない**ので、
  変えるなら出す前に
- 版の番号(`versionCode`)は今は作った時刻から決めている(デバッグ版向け)。リリース版を作るときは、手で決める番号に変える
- 2023年11月13日以降に作った個人の開発者アカウントは、公開の前に「12人以上で14日間のテスト」が必要
- プライバシーポリシー(公開の URL)と、「データ セーフティ」の記入が必要(同期のパスワードを端末に保存していること、
  データはユーザーが選んだサーバーにだけ送ることなど)
- Android では、ストアの外で配るアプリにも開発者の本人確認を求める仕組みが始まっている(国ごとに順に。要確認)

## iOS

`ios/` に Xcode のプロジェクトがある(Swift Package Manager 版)。ビルドには Mac と Xcode が要るので、
今はまだ動かしていない。Mac が使えるようになったら `npx cap sync ios && npx cap open ios`。
通信は Capacitor 標準の CapacitorHttp を使うので、iOS 用に自分で書いたネイティブのコードはない。
Mac で確かめること: 大きな PDF の同期(メモリ)、取り消し(iOS では送っている通信までは止まらない)、
クッキーを持つ通信で Nextcloud が断らないか。画面は明るい色だけなので、`Info.plist` でダークモードを使わない設定にしてある。

## 画面の崩れを防ぐしくみ

### 作り方の決まり

- 幅を数字で決め打ちしない。並べるのは Flexbox / Grid、幅は割合と `max-width`
- 画面の端は `var(--sa-top)` などを使う(`style.css` の先頭)。`env(safe-area-inset-*)` を直接書かない
  (Android のアプリ版で効かないことがあるため)
- タッチの画面で押すものは 28px 以上(なるべく 40px)
- 長い名前は `text-overflow: ellipsis` で省略するか、折り返す

### 自動のテスト(`test/ui/layout.spec.js`)

iPhone(390×844)・小さい Android(360×640)・スマホ横(844×390)・iPad 縦横・PC(1440×900)・切り欠きのあるスマホ縦横の8つ ×
Chromium(Chrome・Android と同じ仕組み)と WebKit(Safari・iPad と同じ仕組み)で、本棚・ダイアログ・ノートの画面などを開き、

1. **決まりごと**: 画面やダイアログが横にはみ出していないか、ボタンが切れたり、ほかのものに隠れたり、
   画面の端(切り欠き・ホームバー)にかかったりしていないか(スクロールして見える部品は見えるところまで動かして確かめる)、
   ボタンの文字があふれていないか、タッチの画面で小さすぎるボタンがないか
2. **見た目の比較**: スクショを撮り、基準の画像(`test/ui/__screenshots__/`)と比べる。0.2% を超えて違えば失敗

GitHub Actions(`.github/workflows/ci.yml`)がプッシュのたびに動かす。失敗したら、実行結果の Artifacts の
`playwright-report` に、基準・今回・違いの3枚の画像が入っている。

- 基準の画像は、文字の描かれ方をそろえるため GitHub Actions(ubuntu-24.04 に固定)の中で作る。新しい画面のテストを足すと、
  その回で基準を作って比べ、ブランチに「基準のスクショを更新」のコミットを足す。
  **CI がコミットを足すので、次にプッシュする前に `git pull --rebase` をする**(しないとプッシュが断られる)
- 見た目をわざと変えたときは、最後のコミットのメッセージに `[update-screenshots]` と書いてプッシュすると、違う画面の基準を作り直す
- CI が足したコミットには、CI が自分でもう一度「確認」を走らせる(GitHub の決まりで、CI のプッシュでは自動では走らないため)。PR のチェックはその結果が付く
- 基準の画像は `.gitignore` に入れてあり、CI だけが足す(手元で作った画像を間違えてコミットしないように)
- 手元で動かすとき: `npm ci && npx playwright install chromium webkit && npm run test:ui`
  (手元の PC では文字の形が違うので、スクショは比べずに決まりごとだけを確かめる。基準の画像は手元で作らない)
- 切り欠き・ホームバーのある端末は、`phone-notch`・`phone-land-notch` で Capacitor と同じく画面の端の幅を入れてまねる
