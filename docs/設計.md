# 大学ノートの設計と GoodNotes 調査からの反映

GoodNotes の調査(リポジトリの外にある `GoodNotes調査メモ.md`。先生の PC の `ドキュメント\大学ノート\` に置いてある)で分かったことを、大学ノートの設計と照らし合わせたもの。
GoodNotes をまねるのではなく、「オフラインで全部使える・同期先を選べる・無料」という大学ノートの方針に合うところだけを取り入れる。

## 1. 調査で分かった GoodNotes の作りと、大学ノートの対応

| GoodNotes | 大学ノート | 状態 |
|---|---|---|
| 正のデータは変更イベントの記録(RocksDB)。画面用の目録は別に作る(CQRS) | 正のデータは op の記録(IndexedDB の `ops`)。画面用の状態は op から作る(`js/model.js`)。一覧用に `notemeta` を別に持つ | 同じ考え方で実装済み |
| 各項目に `{値, 端末番号, カウンタ}` の LWW | 各項目(名前・表紙・ページ順・背景・線の有無・位置・色)に `{ランポート時計, 端末ID}` の LWW | 実装済み |
| 消した線は「削除済み」に移すだけでデータは残す | `stroke.del` は「ない」にするだけで線は残る(元に戻す・同期のため) | 実装済み |
| PDF は丸ごと1つの添付、ページは参照するだけ | PDF は SHA-256 で1つだけ保存、ページは「どの PDF の何ページ目か」 | 実装済み |
| 同期: サーバーは文書ごとの追記専用ログを順に配るだけ。端末はカーソル以降を取りに行き、マージは端末側 | WebDAV に端末ごとの追記専用ログ(`ops/<端末>/<開始>-<終了>.json`)。**この版で端末ごとのカーソルに変更**(下の 2) | 今回 |
| 変更の知らせを WebSocket で受け、知らせが来たら取りに行く | WebDAV には知らせがないので、**フォルダの ETag を「変わったかどうかの目印」に使う**(下の 2) | 今回 |
| 点データはペンの種類ごとに持つ値が違う(tpl 形式)。ふつうのペンは太さに筆圧を焼き込み、鉛筆だけ筆圧・傾きを生で持つ | 線の点は `[x, y, 筆圧]` の3つ組。GoodNotes の取り込みは種類ごとに読み分ける。**この版で鉛筆の読み違いを修正**(下の 3) | 今回 |
| 並び順は文字列の fractional indexing | ページ順は数(小数)で、間に入れるときは前後の中間。数の細かさの限界までは同じ働き | 当面このまま |
| フォルダは「親を指す」方式 + LWW | フォルダはまだない | 次の候補(下の 4) |
| ログイン用のトークンが端末内にそのまま保存されていた | WebDAV のアプリパスワードは IndexedDB に保存(ブラウザには OS の鍵置き場を使う手段がない) | README で「アプリパスワードを使い、通常のパスワードは入れない」と案内 |

## 2. 同期: 端末ごとのカーソル + ETag(この版)

以前は「読んだファイルの名前の一覧」(`seen`)を覚えていて、同期のたびに全端末のフォルダの中身を一覧していた。
使うほど一覧が大きくなり、問い合わせも端末の数だけ増える。

- **カーソル**: 端末ごとに「その端末の op を何番まで読んだか」(`cur[端末] = 終了番号`)だけを覚える。
  ファイル名の終了番号がカーソルより大きいファイルだけを、終了番号の順に読む。
  - ある端末のファイルは、つなげると必ず 1 番から抜けなく並ぶ(書く側は送れたところから続きを書く)ので、
    終了番号の順に読めば「カーソルまでは全部読んである」が保たれる。
  - 書く側の記録が消えて 1 番から書き直したファイル(`000000001-000000500.json` など)も、終了番号が大きければ読む。
    名前の並びだけで比べると、こういうファイルを読み落とす。
  - 同じ op が2回届いても ID で捨てるので、読み直しは害にならない。
  - 以前の版の `seen` は、起動時に端末ごとの最大の終了番号に置き換える(以前の版も番号順に読み、失敗したら止まっていたので安全)。
- **ETag**: `ops/` を一覧するときに各端末のフォルダの ETag も受け取り、前回と同じならそのフォルダの中は見ない。
  Nextcloud などはフォルダの中が変わるとフォルダの ETag も変わる。変化がなければ問い合わせは1回で済む。
  - ETag を返さないサーバーでは毎回中を見る(以前と同じ)。
  - ETag の付け方があやしいサーバーでも取りこぼし続けないように、アプリの起動後の最初の自動同期・その後10回に1回・手動の同期では全部のフォルダを見る。
  - フォルダを最後まで読めたときだけ ETag を覚える。

この形(追記専用ログ + カーソル + 変わったかどうかの目印)は、将来、自前のサーバーや Supabase などに載せ替えるときもそのまま使える。
サーバー側は「端末(または文書)ごとのログを番号順に返す」「変わったら知らせる」だけでよく、マージは今と同じく端末でやる。

## 3. GoodNotes の取り込みの精度(この版)

見本2冊で確かめた: `しかにゅうのーと.goodnotes`(手書き 7,332 本。ふつうのペンと蛍光ペンの形)と `sample2.goodnotes`(ふつうのペン・鉛筆1本・蛍光ペンの形)。

- **鉛筆(ペン種別5)**: 点は `(x, y, 方位角, 傾き, 筆圧)`。以前は3つ目の方位角を太さと読んでいた。
  版数の次の値を基本の太さとして(推測。蛍光ペンの太さと同じ 1.56 が入っているため)、筆圧で細くするように直した。
  式は大学ノート側で決めた近似で、線の中のいちばん強いところ(1 より弱ければ 1)で基本の太さ、筆圧 0 で 0.3 倍。
  見本の鉛筆は1本だけで、筆圧はほぼ 1、書き終わりだけ 0.55 だった。Apple Pencil で強く書いたときに 1 を超える値が入るかは未確認なので、
  線ごとに割って、1 を超えても太さが張り付かないようにしてある。
- **先頭に値が多い線(ペン種別4など)**: 「区間の種類・始点・区間」の3つの並びの位置を型の文字列から探して読むようにした(先頭の値は2つまで)。
  ペン種別4は先頭に値が1つ多いと調査メモにあるが、手元の見本にはないので、作ったデータでだけ確かめている。
- **点のない線**: GoodNotes には点が1つもない線の記録が残っていることがある(しかにゅうのーとで 659 本)。
  以前はこれをページの左上の小さな点として取り込んでいた。何も描かないものとして飛ばすようにした。
  形は分かったのに値がおかしい線も、座標らしい値を探して描くことはせず、飛ばす。

## 4. 次の候補

1. **フォルダ**: ノートに「親フォルダ」を LWW で持たせる(`note.folder` の op)。フォルダ自体も名前・親・削除を LWW で持つ。
   移動は1項目の書き換えだけで、別の端末で同時に動かしても決まる。古い版のアプリは知らない op を無視するので壊れない。
2. **ログの詰め直し**: 端末のフォルダのファイルが増え続けるので、古いファイルを1つにまとめる。
   読む側はカーソルと終了番号で読むので、まとめたファイル(`000000001-000005000.json`)も読み直すだけで済む。
   消すファイルを読んでいる最中の端末がいるので、消すのは少し後にする。
3. **鉛筆の質感**: 今は鉛筆も筆圧つきのペンとして描く。質感のあるペンを作るときは、そのペンの線だけ傾きも持たせる
   (点の並びの形をペンごとに変えられるよう、線のデータに版を持たせる)。
