# App Store・Google Play に出す

かきためノートのアプリ版(`docs/アプリ化.md`)を、App Store と Google Play に出すための手順。
Mac がなくても出せるよう、ストアに上げるアプリは GitHub Actions(`.github/workflows/release.yml`)で作る。

## アプリの中で済ませてあること

| ストアの決まり | かきためノートでの対応 |
|---|---|
| ログインしないと使えないアプリにしない(App Store 5.1.1) | ログインの画面に「ログインせずに、この端末だけで使う」がある |
| アカウントを作れるなら、アプリの中で削除もできる(App Store 5.1.1(v)・Google Play) | 「アカウント」画面の「アカウントを削除する」。Google Play 用の説明のページは `account-deletion.html` |
| Google でログインできるなら、プライバシーに配慮したログイン(Apple でのログインなど)も出す(App Store 4.8) | Apple・Google の両方。iOS で Apple が使えないときは、Google のボタンも出さない |
| 機能を開ける仕組みは、ストアの課金だけ(App Store 3.1.1・Google Play の支払いのポリシー) | アプリ版では特典の欄(クーポンコードの入力と一覧)とプランの名前を出さない。ブラウザ版で付けた特典は、アプリ版でもそのまま効く。ストアでの販売を始めるときに見直す |
| 中身のないウェブの殻にしない(App Store 4.2) | 画面のファイルをアプリに入れている。ネットにつながっていなくても起動して書ける |
| プライバシーマニフェスト | `ios/App/App/PrivacyInfo.xcprivacy`。追跡なし。集めるのはメールアドレス・利用者の ID・ノート・画像 |
| 暗号の輸出の申告 | `Info.plist` の `ITSAppUsesNonExemptEncryption` を false(使う暗号は OS の HTTPS だけ)。毎回の質問が出なくなる |
| カメラなどを使う理由 | `Info.plist` にカメラ(画像を貼るときの「写真を撮る」)と、写真への保存の理由を書いた。書かないと、選んだ瞬間にアプリが落ちる |
| 審査の担当者がログインできる | 決めておいた番号で入れる審査用のアカウント(`server/README.md` の「ストアの審査用のアカウント」) |

## 利用規約の料金について

まだストアで買えない Pro・Max の料金が、アプリから開ける利用規約に載っていると審査で問われるため、2026年11月21日に利用規約の第3条の料金を「準備中」にした
(先生の判断。11月28日施行)。まだ誰も購入しておらず、売っていない料金を消すだけで利用者に不利な変更はないため、第10条の「事前のお知らせ」は施行日を1週間あとにすることで代えた。
なお、規約の第3条・第8条・第10条にある「アプリ内でお知らせ」には、まだアプリの中のお知らせの仕組みがない。次に規約を変える前か、ストアで販売を始める前に用意する。
ストアで販売を始めるときは、アプリ内課金を作り、料金を書き戻し、アプリ版の特典の欄・プラン名の表示(`js/account-ui.js`)を見直す。

## Google Play

### 1. アップロード鍵を作る(最初の1回)

Google Play では、自分で持つ「アップロード鍵」で署名して上げ、配る用の鍵は Google が預かる(Play App Signing)。
アップロード鍵をなくしても Google に頼めば作り直せるが、パスワードと一緒に安全な場所に控えておく。**リポジトリには絶対に入れない。**

Windows の PowerShell で(Android Studio に入っている keytool を使う):

```
& "C:\Program Files\Android\Android Studio\jbr\bin\keytool.exe" -genkeypair -v -keystore upload.jks -alias upload -keyalg RSA -keysize 2048 -validity 10000
[Convert]::ToBase64String([IO.File]::ReadAllBytes("upload.jks")) | Set-Content -NoNewline upload.b64
```

聞かれるパスワードを決めて控える。名前などの質問は、氏名か屋号を入れればよい。

### 2. GitHub に鍵を入れる(最初の1回)

リポジトリの Settings → Secrets and variables → Actions → New repository secret で、次の4つを入れる。

| 名前 | 中身 |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | `upload.b64` の中身 |
| `ANDROID_KEYSTORE_PASSWORD` | 1 で決めたパスワード |
| `ANDROID_KEY_ALIAS` | `upload` |
| `ANDROID_KEY_PASSWORD` | 鍵のパスワード(聞かれなかった・同じなら入れなくてよい) |

### 3. .aab を作る

GitHub の Actions → 「ストア用に作る」→ Run workflow。バージョン(初回は `1.0`)と「Android だけ」か「両方」を選ぶ。
終わったら、実行結果の Artifacts の `kakitame-note-android-aab` をダウンロードし、中の `.aab` を Play Console に上げる。

- バージョンの番号(versionCode)は作った時刻から決まるので、毎回自動で大きくなる
- 同じバージョン(1.0 など)で作り直してもよい。ストアに出すたびに上げるのは、利用者に見せるバージョンだけ

### 4. Play Console でやること

1. 開発者アカウントを作る(25ドル・1回だけ。本人確認がある)
2. 「アプリを作成」: 名前「かきためノート」、言語は日本語、アプリ、無料
3. 内部テストのトラックに 3 の .aab を上げる。最初に上げたときに Play App Signing を有効にする
4. 2023年11月13日以降に作った個人のアカウントは、**12人以上で14日間のクローズドテスト**をしてからでないと製品版に出せない。
   テストの人はテストに参加し、14日間続けて参加したままでいる必要がある。終わったら Play Console から製品版へのアクセスを申し込む。
   また、新しい個人のアカウントは Play Console アプリで Android 端末の確認を求められる
5. 「アプリのコンテンツ」を埋める(答えは下の「ストアの質問への答え」)
6. ストアの掲載情報(説明・アイコン 512×512・フィーチャーグラフィック 1024×500・スクリーンショット)

## App Store

### 1. Apple でやること(最初の1回)

1. [Apple Developer Program](https://developer.apple.com/programs/) に登録する(年会費あり)。Apple ID の2ファクタ認証が要り、
   個人の登録は iPhone・iPad の「Apple Developer」アプリで本人確認をする。個人で登録すると、App Store の販売元には本名が出る。
   屋号(かきためノート運営事務局)を出したいときは法人での登録(D-U-N-S 番号が要る)。
   アカウントの削除のページなどに書いた運営者の名前と、ストアに出る名前が違うと Google Play で問われることがあるので、そろえ方を決めておく
2. [Identifiers](https://developer.apple.com/account/resources/identifiers/list) で App ID を作る。Bundle ID は Explicit で `io.github.jagjagyt.daigakunote`
   (Apple でのログイン用の Services ID とは別のもの。`server/README.md` の手順で作ったのは Services ID)
3. [App Store Connect](https://appstoreconnect.apple.com/) の「アプリ」→「+」→ 新規 App。プラットフォーム iOS、名前「かきためノート」、言語は日本語、
   バンドル ID は 2 のもの、SKU は `kakitame-note` など自由
4. App Store Connect の「ユーザとアクセス」→「統合」→「App Store Connect API」→「チームキー」で、アクセスを **Admin** にしたキーを作る。
   `.p8` のファイルは1回しかダウンロードできないので控える。画面に出る「Issuer ID」と「キー ID」も控える
   (Admin にするのは、署名の証明書を GitHub の Mac から作れるようにするため)
5. [Membership](https://developer.apple.com/account#MembershipDetailsCard) の「チーム ID」(10文字)を控える
6. [Devices](https://developer.apple.com/account/resources/devices/list) に、手元の iPad(か iPhone)を1台登録する。
   GitHub の Mac は、アーカイブを作るときに開発用のプロファイルを作るので、登録した端末が1台もないと失敗する。
   端末の UDID は、Windows の iTunes で端末をつなぎ、概要の画面の「シリアル番号」を押すと出る
7. App Store Connect で EU のデジタルサービス法の「トレーダー」かどうかを聞かれる。今は収益がないので「トレーダーではない」でよい
   (トレーダーにすると住所・電話番号が公開される)。有料プラン・広告を始めるときに見直す。
   無料の App なら、「契約/税金/口座情報」の手続きは要らない(有料のプランを売るときに要る)

### 2. GitHub に鍵を入れる(最初の1回)

| 名前 | 中身 |
|---|---|
| `APPLE_TEAM_ID` | チーム ID |
| `APPSTORE_API_KEY_ID` | キー ID |
| `APPSTORE_API_ISSUER_ID` | Issuer ID |
| `APPSTORE_API_KEY_P8` | `.p8` のファイルをメモ帳で開いた中身をそのまま(`-----BEGIN PRIVATE KEY-----` の行から) |

### 3. 作って上げる

Actions → 「ストア用に作る」→ Run workflow で「iOS だけ」か「両方」。GitHub の Mac が署名して App Store Connect に上げる。
数十分で App Store Connect の TestFlight に出る(最初は「暗号の書類はありません」の確認なしで出るはず)。

- 署名の証明書とプロファイルは、Xcode が API キーで Apple から取ってくる(Mac での作業はない)
- 「証明書の数が上限に達した」で失敗したら、[Certificates](https://developer.apple.com/account/resources/certificates/list) で古い「Apple Development」の証明書を取り消してから、もう一度走らせる
  (GitHub の Mac は毎回まっさらなので、走らせるたびに開発用の証明書を作ることがある)
- TestFlight の「内部テスト」に自分を入れると、iPhone・iPad の TestFlight アプリから入れて試せる(審査なし)

### 4. 審査に出す

App Store Connect のアプリのページで、次を埋めて「審査へ提出」。

- スクリーンショット: iPhone 6.9 インチ(1320×2868)と iPad 13 インチ(2064×2752)。iPad にも対応しているので両方要る。
  実機の画面を撮った場合は、この大きさに合わせる(縦横比が近ければ、余白を足して大きさをそろえてよい)
- サポート URL: 問い合わせ先が書いてあるページ。今は `https://jagjag-yt.github.io/daigaku-note/account-deletion.html` に問い合わせ先がある。専用のページを作るならそちら
- 説明・キーワード・サポート URL・プライバシーポリシーの URL
- 「App のプライバシー」(下の答え)
- 年齢制限の質問(下の答え)
- 「App Review に関する情報」のサインイン情報と、メモ(下の文)
- ビルド: 3 で上げたもの

## 審査用のアカウント

審査の担当者はログインの番号のメールを受け取れないので、決めておいた番号で入れるアカウントを用意する。

以下のコマンドは、どれも `server/` フォルダで打つ。

1. サーバーに入れる(`server/README.md` の「ストアの審査用のアカウント」)
   ```
   npx wrangler secret put REVIEW_EMAIL
   npx wrangler secret put REVIEW_CODE
   ```
   このためにサーバーを新しいものに配信しておく(`npx wrangler deploy`)
2. ブラウザ版で「アカウントを作成」→ REVIEW_EMAIL → 番号に REVIEW_CODE を入れて作る
3. 365日使われないと片づけの対象になるので、`node scripts/coupon.mjs make --count 1 --perk adfree --note "審査用"` で作ったコードを、ブラウザ版でこのアカウントに使っておく
   (広告はまだないので、見た目も容量もふつうの無料の利用者と同じ。Pro・Max は容量が変わるので使わない)
4. 見本のノートを1冊作っておくと、審査の担当者が同期を試しやすい
5. 審査の担当者は、アカウントの削除を試すことがある。審査に出す前と、審査が終わったあとに、このアカウントが残っているかを確かめる
   (消されていたら 2・3 をやり直す)
6. このアドレスと番号は推測されにくいものにし(`review-` に乱数を付けたアドレスなど)、**審査が終わるたびに番号を変える**
   (`npx wrangler secret put REVIEW_CODE` で入れ直すだけ。サーバーの配信は要らない)。番号は決まっているので、長く同じままにすると当てられるおそれがある

## ストアの質問への答え

アプリやサーバーの扱いを変えたら、ここと `privacy.html`・`PrivacyInfo.xcprivacy` をそろえる。

### App Store の「App のプライバシー」

- データの収集: あり。トラッキング: しない
- 連絡先情報 → メールアドレス: App の機能・ユーザに関連付けられる
- ID → ユーザ ID: App の機能・ユーザに関連付けられる(アカウントの ID、Apple・Google の ID)
- ユーザコンテンツ → 写真やビデオ: App の機能・ユーザに関連付けられる(ノートに貼った画像を同期のために預かる)
- ユーザコンテンツ → その他のユーザコンテンツ: App の機能・ユーザに関連付けられる(ノート・PDF)
- ほか(位置情報・購入・閲覧履歴・診断など): 収集しない

### Google Play の「データ セーフティ」

- データを収集する: はい。第三者と共有する: いいえ(サーバー・メールの送信の会社は「サービス提供者」なので共有に当たらない)
- 送信中のデータは暗号化される: はい
- データの削除をリクエストできる: はい。URL は `https://jagjag-yt.github.io/daigaku-note/account-deletion.html`
- 個人情報 → メールアドレス: 収集・必須ではない(ログインしなくても使える)・アプリの機能、アカウント管理、デベロッパーからの連絡(長く使われていないときのお知らせ)
- 個人情報 → ユーザー ID: 収集・必須ではない・アカウント管理
- 写真と動画 → 写真: 収集・必須ではない・アプリの機能
- ファイルとドキュメント: 収集・必須ではない・アプリの機能
- そのほか: 収集しない

### 年齢制限(App Store)・コンテンツのレーティング(Google Play)

暴力・性的な内容・ギャンブル・薬物などは、すべて「なし」。利用者どうしのやり取り(チャット・公開の投稿)はなし(ノートは本人の端末とアカウントの中だけ。
共有は利用者が自分でファイルを書き出して渡すだけ)。ウェブを自由に見る機能はなし。広告はなし(入れるときは答えを変える)。

### Google Play のそのほかの質問

- アプリのアクセス権: 一部の機能に制限あり → 審査用のアカウントのメールアドレスと番号を書き、「メールアドレスを入れて『番号を送る』を押し、番号の欄に REVIEW_CODE を入れる。
  『アカウントはありません』と出たら『アカウントを作成』から同じアドレスと番号で作る」と説明する
- 広告: 含まない
- ターゲット ユーザー: 13歳以上(子ども向けにしない。子ども向けにすると別の決まりがかかる)
- ニュースアプリ・健康・金融・政府: いいえ

### App Review へのメモ(App Store)

```
This is a handwriting note app for students (Japanese UI). It works fully offline without an account:
on the first screen, tap "ログインせずに、この端末だけで使う" (Use on this device without signing in).

An account is optional and is only used to sync notes between devices. Sign-in uses a 6-digit code sent by email,
or Sign in with Apple / Google. For review, please use the account below; no email is sent to it,
and the fixed code works as the emailed code.

  Email: (REVIEW_EMAIL)
  Code:  (REVIEW_CODE)
  Steps: ログイン → enter the email → 番号を送る → enter the code
  If it says the account does not exist (e.g. after testing deletion), use アカウントを作成 with the same email and code.

Account deletion: Account button (top right of the shelf) → アカウントを削除する → アカウントを削除 → 削除する.
No purchases are possible in this version (no in-app purchases, no links to buy elsewhere) and there are no ads.
```
